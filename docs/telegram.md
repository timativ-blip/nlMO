# Telegram-бот и мини-приложение

## Подключение

Бот команды — [@nl_MO_bot](https://t.me/nl_MO_bot). Откройте сайт, войдите в свой кабинет, затем выберите **Профиль → Подключить Telegram**. Перейдите по созданной ссылке и нажмите «Старт» в личном чате с ботом. Ссылка одноразовая и действует 24 часа. Пароль в сообщениях боту вводить не нужно.

Один Telegram связывается с одной учётной записью сайта. Для смены кабинета сначала выполните `/stop`. Если кабинет уже подключён к другому Telegram, отключите прежнее подключение в профиле сайта.

## Сайт внутри Telegram

Кнопка **Открыть сайт** возле строки сообщения и команда `/app` запускают тот же Командный центр в мини-приложении. Кнопки в новых уведомлениях открывают нужную задачу или отчёт. После подключения бот узнаёт кабинет по проверенной подписи Telegram и создаёт обычную сессию сайта. Роли, данные, приёмка результатов, темы и остальные функции общие с сайтом.

Если Telegram ещё не привязан, выберите **Войти почтой**, затем подключите бота в профиле. Если данные входа устарели, закройте мини-приложение и снова откройте его кнопкой в боте. Обычный вход почтой и паролем остаётся доступен.

## Заполнение сообщениями

| Команда | Действие |
| --- | --- |
| `/daily` | Отчёт дня: дата, что сделано, план, проблемы |
| `/weekly` | Недельный отчёт: округ и неделя, выводы, проблемы, план |
| `/tasks` | Собственные задачи и задачи соисполнителя, доступные для сдачи результата |
| `/resume` | Продолжить незавершённый черновик |
| `/cancel` | Отменить текущий черновик |
| `/help` | Открыть меню |
| `/stop` | Отключить Telegram от кабинета |

Бот задаёт вопросы по одному. Для необязательного поля можно отправить `-` или нажать «Пропустить». «Назад» возвращает к предыдущему шагу. Перед записью бот показывает заполненные данные и кнопку подтверждения. До подтверждения отчёт или результат остаётся черновиком в боте.

Отчёт дня можно заполнить за сегодня или два предыдущих дня, по московскому времени. Недельный отчёт доступен руководителю и координатору своего округа. Если для новой недели отчёт ещё не создан, бот подготовит его при подтверждении: открывать сайт для этого не требуется. Отправленные и принятые недельные отчёты закрыты для заполнения.

Результат может сдать ответственный или соисполнитель задачи в статусе «Новая» или «В работе». Для задачи с показателем бот попросит число. Можно добавить до 10 материалов: ссылки, фотографии и файлы до 10 МБ. После материалов нажмите «Готово» или отправьте `/done`. Результат уйдёт на прежнюю проверку; подтверждение выполнения остаётся отдельным действием проверяющего. Подтверждённые результаты учитываются в прежних отчётах и аналитике.

Черновик хранится на сервере два дня с последнего принятого сообщения. Его можно продолжить после закрытия Telegram. Отмена черновика не изменяет уже сохранённые данные сайта. Если запись изменилась на сайте во время заполнения, бот сохраняет ваш текст и предлагает **Обновить версию и сверить**. Для изменившегося показателя задачи значение потребуется ввести заново. Замена отчёта выполняется только после нового подтверждения.

Заполнение и привязка работают в личном чате. Повторная доставка Telegram не создаёт повторных результатов, комментариев и уведомлений.

## Серверная часть

1. Примените `supabase/migrations/20261031192535_telegram_miniapp_and_emergency.sql` в рабочем проекте `wlqwwhshqrqanapsnsik`.
2. Опубликуйте функцию `telegram` вместе с `handler.ts`, `protocol.ts` и `conversation.ts`. Зависимость Supabase JS закреплена на `2.45.4`. `verify_jwt=false` задан в `supabase/config.toml`: вебхук проверяет секретный заголовок, мини-приложение — HMAC подпись, административная настройка — Supabase JWT и актуальную роль.
3. Существующий `TELEGRAM_BOT_TOKEN` остаётся секретом Edge Function. `hook_secret`, `functions_url` и HTTPS `app_url` остаются в закрытой `app_secrets`. Не переносите токен в браузер или ссылки файлов.
4. В настройках сайта нажмите **Обновить меню и подключение**. Установятся команды, кнопка мини-приложения и вебхук для `message` и `callback_query`. Подключения и очередь сообщений сохраняются. Серверный вызов с текущим секретом и `action=configure` выполняет ту же настройку без пользовательской рассылки.
5. Проверьте `getWebhookInfo`, кнопку меню и команды. После этого публикуйте клиент. Старые уведомления продолжают приходить через прежний триггер `notifications`.

`telegram_bot_drafts`, `telegram_bot_updates` и `telegram_login_claims` закрыты от браузерных ролей. Три RPC доступны только серверной роли. Обновление диалога, запись результата и квитанция Telegram выполняются одной транзакцией; состояние защищено номером версии, сообщения — `update_id`, кнопки — одноразовым значением шага. Права и версия документа повторно проверяются при подтверждении. Для записи устанавливается идентификатор действующего пользователя, поэтому прежние триггеры статусов, журналирование и уведомления сохраняются.

Вход мини-приложения проверяет все поля `initData`, подпись HMAC-SHA-256 и возраст данных до 10 минут. Привязка определяется по подписанному Telegram ID и закрытой таблице, роль берётся из профиля базы. Одноразовый хеш и ограничение попыток защищают выдачу сессии. Пароль не передаётся в Telegram. Служебный ключ и токен бота не попадают в браузер; сессия возвращается с `Cache-Control: no-store`. Фотографии и файлы копируются в прежний приватный контейнер `attachments`, в записи хранятся ссылки `sb://attachments/…`.

Для очистки служебных квитанций и просроченных входов миграция добавляет ежечасное задание `telegram-bot-cleanup`. Исходные бизнес-таблицы, их политики и правила приёмки не меняются. Миграция совместима со старой функцией и клиентом; сначала устанавливается база, затем функция, затем сайт.

## Проверки

`npm run test:telegram` проверяет типы функции, подпись и повторное использование входа, диалоги, ограничения ролей и кнопок, а также полный путь HTTP вебхука → диалог → временный PostgreSQL → ответ Telegram. Отдельно проверяются новая неделя, изменения на сайте во время заполнения, откат при ошибке уведомления, фото, потерянный ответ и независимая приёмка. Сетевые запросы Telegram и хранилище в этих проверках подменены; рабочая команда не получает тестовых сообщений.

Источники протоколов: [Telegram Mini Apps](https://core.telegram.org/bots/webapps), [Telegram Bot API](https://core.telegram.org/bots/api), [Supabase Generate Link](https://supabase.com/docs/reference/javascript/auth-admin-generatelink), [Supabase Verify OTP](https://supabase.com/docs/reference/javascript/auth-verifyotp).
