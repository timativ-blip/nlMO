# Единый источник «Пиши-Делись»

Причина ошибочной сводки 2 ноября 2026 года: клиент сайта дополнял старую выгрузку листом «11 сезон», а серверный `digest` обращался к `media-pd`, в котором оставался только сентябрьский архив. Поэтому бот видел последнюю публикацию 30 сентября. Фраза «таблица не обновлялась» также была неверной: дата последней публикации не подтверждает дату редактирования таблицы.

Теперь `media-pd` получает архив, список людей по округам и публичный CSV листа «11 сезон». Объединение выполняется на сервере общим модулем `supabase/functions/_shared/media-timeline.ts`. Сайт и бот читают готовый одинаковый поток. Сентябрь сохраняется; повторные сентябрьские строки нового листа не прибавляются к архиву. Октябрь берётся из 11 сезона. Если в этом же листе появляются ноябрьские строки, они тоже сохраняются с фактическим номером источника 11, без выдумывания нового сезона.

На момент проверки 02.11.2026 в новом листе обнаружена 371 октябрьская публикация, последняя — 31.10.2026. Эти цифры отражают даты строк, а не время редактирования Google-таблицы.

Сводка показывает число постов за отчётную неделю и при необходимости уточняет, по какую дату есть публикации. Нулевой день в конце недели не скрывает всю недельную статистику и не превращается в обвинение в устаревшей таблице. Напоминания о неактивности блокируются при сбое источника или отсутствии недавних публикаций, чтобы не присылать ложные сигналы.

Обновление источника проверяется раз в минуту при обращении. При недоступности источника сервер может вернуть последнюю успешную выгрузку не старше 15 минут с `sourceStatus: stale`; сайт показывает предупреждение, а бот не использует её для сигналов неактивности. Более старые данные возвращаются как ошибка, а не как успешная актуальная статистика. Поле `updated` — время получения выгрузки, не дата редактирования исходной таблицы.

Порядок установки:

1. Развернуть `media-pd` с `index.ts`, `handler.ts` и `../_shared/media-timeline.ts`.
2. Развернуть `digest` с `index.ts`, `pd-summary.ts` и тем же общим модулем для типов. Сохранить прежние секреты и проверку `x-hook-secret`; новых секретов и миграций нет.
3. Проверить публичный `media-pd`: в ответе должны быть `seasons["2026-10"] = 11`, октябрьские строки и `sourceStatus: ok`.
4. Проверить `digest` в режиме `{ "action": "weekly", "dry": true }` с внутренним секретом. Этот режим формирует текст без записи уведомлений и отправки Telegram.
5. Опубликовать клиент штатным GitHub Pages workflow. Прежняя ссылка сайта сохраняется.

Проверки: `npm run test:media` (типы сервера, общий парсер, месяцы, загрузчик, кеш, недоступность нового листа и текст сводки), `npm run build`. Остальные штатные проверки также входят в CI. Проверка не меняет Google-таблицу и не рассылает тестовые сообщения пользователям. Уже отправленные сообщения Telegram не переписываются установкой нового кода.
