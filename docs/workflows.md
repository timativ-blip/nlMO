# Поручения, шаблоны, черновики и сопоставления

## Поручение для нескольких округов

Откройте **Задачи → По округам**. Заполните поручение, выберите округа и проверьте ответственного для каждого. По умолчанию подставляется действующий координатор, если он назначен. При отсутствии координатора нужно выбрать человека вручную. Руководитель и штаб могут выбирать округа и сотрудников штаба; координатор работает со своим округом и его командой.

Один запуск создаёт отдельную обычную задачу на каждый выбранный округ. У задач свои чек-листы, сроки, результаты и приёмка. Подтверждение одной не закрывает остальные. Они попадают в прежний список задач, календарь сроков, уведомления, отчёты и показатели по прежним правилам. Повторная отправка того же запроса возвращает созданные задачи. Если хотя бы один округ или ответственный недоступен, весь запуск отклоняется.

## Шаблоны и повторения

В **Задачи → Шаблоны и повторения → Шаблоны** сохраните типовое название, описание, приоритет, чек-лист, ссылки, показатель, мероприятие и число дней на выполнение. Личный шаблон доступен автору и руководителю. Штаб и руководство могут сделать шаблон общим для тех, кто ставит задачи. Чужой общий шаблон можно использовать, но редактировать его могут автор и руководитель. Архивирование убирает шаблон из выбора.

Шаблон копируется в новое поручение. Изменение или архивирование шаблона не меняет уже созданные задачи и расписания.

Во вкладке **По округам** выберите еженедельную или ежемесячную постановку, первый день, время **по Москве** и число дней на выполнение. До первого запуска задачи не создаются. Если время первого запуска сегодня уже прошло, первый выпуск создаётся сразу. Следующие выпуски создаёт сервер, даже когда сайт закрыт. Если в месяце нет выбранного числа, используется последний день месяца: 31 октября → 30 ноября → 31 декабря.

Во вкладке **Повторения** можно приостановить будущую постановку и возобновить её. Готовые задачи сохраняются. Для изменения состава поручения приостановите прежнее расписание и нажмите «Создать похожее»; копирование само по себе не останавливает старое расписание.

После простоя сервер создаёт один текущий выпуск, а не все пропущенные. Срок выполнения отсчитывается от фактического дня постановки. Перед каждым запуском сервер заново проверяет роль автора, доступ к округам и действующих ответственных. При ошибке весь выпуск отменяется, расписание приостанавливается, причина появляется во вкладке «Повторения». После исправления можно возобновить его.

## Незавершённые формы

Черновик сохраняется при каждом изменении в формах новой задачи, поручения по округам, шаблона, сдачи результата, ежедневного и недельного отчёта. Его можно восстановить после закрытия формы, перехода в другой раздел и перезагрузки страницы. Ежедневные отчёты разделены по дате, результаты — по задаче, недельные отчёты — по отчёту. Учётные записи, рабочая база и деморежим используют отдельные ключи.

Черновики хранятся в этом браузере на этом устройстве до 30 дней и не синхронизируются между устройствами. Кнопка «Удалить черновик» возвращает форму к последней сохранённой версии. Если память браузера недоступна или переполнена, форма сообщает об этом. Текст не следует считать сохранённым на устройстве при таком сообщении.

После отправки черновик очищается только при подтверждении сервера. При ошибке отправки текст остаётся. Подтверждение старой отправки не удаляет текст, дописанный во время ожидания ответа. При изменении серверной версии несохранённые поля сохраняются отдельно и показывается предупреждение. Повторная попытка создания обычной задачи использует прежний идентификатор, чтобы потерянный ответ не создал копию.

## Авторы медиа

Откройте **Медиа → Без округа → автор → Привязать автора**. Можно выбрать человека из команды или только округ. Связать с человеком можно только в его действующем округе; координатор может работать со своим округом, штаб и руководство — со всеми.

Сопоставление применяется к нераспределённому автору во всех месяцах и сезонах, в «Медиа», «Пульсе области» и медиааналитике. Если у выбранного человека уже есть единственная запись с тем же именем в округе, посты объединяются с ней. Число постов, просмотров и сумма баллов не меняются. Привязки исходного документа имеют приоритет; они не переписываются. Автоматического угадывания человека нет.

Во вкладке «Без округа» кнопка **Сопоставления** открывает реестр. «Отменить привязку» возвращает исходное распределение; история изменения остаётся в журнале. При смене округа человека или отключении его учётной записи персональное сопоставление перестаёт применяться, пока его не исправят.

## Установка серверной части

1. Проверьте идентификатор рабочей базы из настроек сайта: `wlqwwhshqrqanapsnsik`.
2. Примените миграцию `20261031155734_task_workflows.sql`. Она добавляет `task_templates`, `task_schedules`, `media_matches`, закрытые квитанции `task_workflow_requests`, RLS, журналирование и один публичный RPC `launch_task_workflow`. Прежние таблицы задач и отчётов, их политики и триггеры не меняются.
3. Убедитесь, что установлено расширение `pg_cron`. Миграция регистрирует задание `task-workflows` с частотой раз в минуту и командой `select app_private.run_task_schedules()`. Если расширение не было установлено при миграции, включите его и зарегистрируйте это задание перед использованием повторений.
4. Проверьте, что три новые документные таблицы добавлены в публикацию `supabase_realtime`. Клиент также перечитывает их раз в минуту. Загрузка этих данных выполняется отдельно от первоначальной загрузки приложения: при недоступности новых инструментов прежние задачи и отчёты остаются доступны.
5. Публикуйте клиент после успешной проверки базы. Новые серверные таблицы обратно совместимы со старым клиентом, поэтому установка сервера выполняется первой. Откат клиента не удаляет данные и не останавливает активные расписания; перед откатом при необходимости приостановите их.

Планировщик находится в `app_private`, не публикуется через API и недоступен `anon` и `authenticated`. Он повторно проверяет права автора перед постановкой, использует блокировку строки и отдельную транзакцию для каждого выпуска. Обычный RPC выполняется с правами вошедшего пользователя и прежними правилами задач.

## Проверки разработки

```sh
npm run test:startup
npm run test:analytics
npm run test:media
npm run test:workflows
npm run build
```

`test:workflows` использует временный PostgreSQL в PGlite с прежними правилами задач и новой миграцией. Проверяются транзакционный откат при ошибке второго округа, права координатора, повторные запросы, прежняя независимая приёмка, закрытые шаблоны, месяцы разной длины, запуск без браузера, простой и остановка при потере прав. Чистые проверки охватывают расчёты, разделение черновиков, поздние ответы и обратимые сопоставления без двойного счёта. Рабочие записи эти проверки не используют.
